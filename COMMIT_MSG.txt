IEC61850ANALYZER v0.6.2 - MMS Active: Control (commands)

Commands to the IED from the tab MMS / Active. Off by default; switched
on with the checkbox 'Control (commands)' and a warning.

- Right-click a data object -> Control... (window like the Control
  window of IEDScout)
- Before a command: ctlModel, sboTimeout, stVal / q, Loc, Mod / Beh of
  the LN are read; warnings for status-only, local, Beh not on
- ctlVal (BOOLEAN, Tcmd lower / higher / stop, INTEGER, FLOAT,
  AnalogueValue), originator category station-control, originator
  identification = name of the PC, Synchrocheck and Interlock-check set,
  Test not set
- All control models: direct / SBO with normal / enhanced security -
  Select (SBO / SBOw), Operate, Cancel, CommandTermination awaited with
  a timeout, LastApplError with AddCause in plain words
- Every command is confirmed and written to
  IEC61850ANALYZER_commands.csv in the home folder
- Settings (SP / SG / SE) and RCBs are never written
- Big LNs (GGIO2 / GGIO3 / LLN0 of GE UR) whose type does not fit into
  one PDU (service error pdu-size): types and values read level by level
  (LN$FC, LN$FC$DO ...) - Values, Monitor, Data sets and Control work;
  MMS errors in plain words
- Log of the Active tab: InformationReport / CommandTermination /
  LastApplError decoded
- Antivirus false positive (Defender) on the exe: the program no longer
  starts anything as administrator and does not call PowerShell - the
  window 'IED IP on this PC' shows and copies the netsh commands; DHCP of
  the adapter is read from the registry; exe built without UPX (--noupx)

Tested with the libiec61850 control server: the 4 control models,
Cancel, negative CommandTermination, Operate without Select ->
Object-not-selected.
